# Better Stack error shipping with request correlation and graceful shutdown

This change adds a stdlib-only Better Stack `slog` sink, bounded asynchronous delivery, request/user correlation, panic capture, health counters, and graceful application shutdown. Request correlation wraps Echo logging and recovery, the existing JSON console handler remains first in the fan-out, and `Echo.Shutdown` returns before the shipper is closed. ERROR is the default shipping threshold, WARN is opt-in, and panic recovery emits one bounded correlated `slog` error. The delivery lifecycle still has blocking defects around shutdown, 402 suspension, and concurrent 403 disable.

Watch for: **confirmed** in-flight batches are abandoned when close starts instead of entering the final drain; **confirmed** 402 suspension consumes and drops queued events and can be bypassed by close; **confirmed** a producer racing the 403 queue drain can strand an event permanently.

**Verdict**: NEEDS_CHANGES

## High-level view

Configuration is resolved once, defaults shipping to ERROR, and enables WARN only explicitly. Startup diagnostics bypass shipping, the console handler remains behaviorally isolated, and the `logging` package has no third-party dependencies. Echo middleware ordering and recovery produce a correlated response header and one panic record, and application shutdown invokes `app.Shutdown` before `shipper.Close`.

Close uses a bounded one-attempt drain, but it cancels ordinary delivery before transferring ownership of an in-flight batch. That batch is counted as abandoned before final drain starts, so it is neither retried under the close budget nor represented in `CloseResult`.

The suspended state does not suspend queue consumption: the delivery loop keeps removing events and drops each triggered batch. The close-only sender also ignores suspension, allowing shutdown to send during the 15-minute no-request window.

The 403 path changes state and drains the channel without the mutex that makes producer state-check/send atomic. A producer already inside admission can send after the drain sees an empty queue, leaving an event permanently stranded.

<summary>Issues (5)</summary>

1. **In-flight close handoff** — **confirmed** close cancellation terminally abandons a batch owned by ordinary delivery before final drain can attempt it. Transfer unresolved ownership into the bounded close drain and include its outcome in `CloseResult`.
2. **Suspension backlog loss** — **confirmed** the delivery loop consumes and drops events during a 402 suspension instead of buffering up to queue capacity. Disable queue consumption while suspended and resume it at the first eligible flush boundary.
3. **Suspension bypass on close** — **confirmed** `transmitFinal` sends while state is suspended. Guard close-time sends on enabled state or explicitly revise the requirements to permit a shutdown exception.
4. **403 admission race** — **confirmed** a producer can enqueue after the permanent-disable drain has observed an empty queue. Serialize the state transition and drain with the existing admission mutex.
5. **Lifecycle test blind spots** — **confirmed** tests do not close an in-flight ordinary request, sustain arrivals through suspension, close while suspended, or force the 403 producer/drain interleaving. Add deterministic tests for those transitions.

<details><summary>Details</summary>

## Close cancels an in-flight batch before the final drain can own it

**Confirmed.** `Close` calls `signalCloseLocked`, which cancels `closeCtx` and closes `closeDone` before waiting for delivery (`logging/close.go`). An ordinary `transmit` inside `IngestClient.Send` returns a retryable cancellation; `waitBeforeRetransmit` sees `closeDone`, releases the batch, and records `reasonAbandonedBatch` (`logging/shipper.go`). Delivery then clears `pending`, so the close arm calls `finalDrain` without that batch.

This contradicts Requirements 9.3 and 9.12 and makes `CloseResult` under-report shutdown loss because the drop occurs before `finalDrain` starts accumulating its result. Transfer a canceled or backing-off batch into final drain without terminal accounting, then give it the one bounded close-time attempt. A regression test should close while the ingest request is blocked and assert both the wire behavior and `CloseResult`.

## 402 suspension drops the backlog instead of preserving queue capacity

**Confirmed.** `suspendTransmission` sets `stateSuspended`, but `deliverOnce` keeps its queue receive arm active. At a batch-size trigger or flush tick, `transmit` reaches `cannotTransmit`, releases the events, and records `reasonNonRetryable` without sending (`logging/shipper.go`). Events are drained and dropped throughout suspension rather than buffered for resumption.

Requirements 7.10 and 7.12 specify zero transmission while admission continues up to queue capacity, followed by resumption at the first eligible flush boundary. Gate the receive arm while suspended, then test buffered delivery after 15 minutes and queue-full drops during the window.

## Final drain can transmit during the 402 no-request window

**Confirmed.** `transmitFinal` rejects only a nil client or `stateDisabled`; `stateSuspended` proceeds to `IngestClient.Send` (`logging/close.go`). `Close` can therefore create an HTTP request during the 15-minute no-transmission period required by Requirement 7.10.

Guard final-drain transmission on `stateEnabled` and define suspended events' terminal close accounting within the five-second budget. If shutdown should override suspension, document that exception in the requirements and state machine before retaining this behavior.

## 403 disable can miss a concurrent producer

**Confirmed.** `enqueue` holds `lifecycleMu` across its disabled-state check and channel send, but `disableAfterTokenRejection` does not hold that mutex around its state store and non-blocking drain (`logging/shipper.go`). A producer can pass the state check, pause, then send after the drain observes empty. Disabled state prevents future consumption, and the event is never counted dropped.

This violates Requirement 7.8. Make permanent disable and queue drain atomic with admission using `lifecycleMu`, then force that interleaving in a race-focused test and assert zero queue depth with the event attributed to dropped.

## Lifecycle tests do not exercise ownership transitions

**Confirmed.** `make test`, `go test -race ./logging/...`, `go vet ./...`, and `make format-check` all pass. Existing close tests drain an unstarted shipper or test close-owned work; they do not close while ordinary delivery owns a blocked request. Suspension and 403 tests do not cover sustained suspended arrivals, close during suspension, or the producer/drain race, allowing all four defects above through the suite.
